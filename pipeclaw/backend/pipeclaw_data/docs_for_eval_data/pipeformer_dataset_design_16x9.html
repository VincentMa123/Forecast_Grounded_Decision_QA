PIPEFORMER DATASET

面向管网预测与调度的单轮评测数据集设计

该数据集对应 Pipeline_Full_Life_Cycle_Test_Dataset-v7.json，核心目标不是做开放式聊天，而是把长流程管网决策压缩成可复现、可打分、可比较的单轮任务。数据集同时覆盖 prediction 与 dispatch 两类问题，并把每个场景锚定到明确的边界变量、扰动设定、工程偏好和输出格式。

设计主线：真实对象锚定、任务类型分层、边界变量唯一、评测器可直接解析。

这样做的好处是，Agent 的结果既能被运行器消费，也能被 evaluator 拆成预测质量、约束一致性、调度正确性和报告可用性等维度。

适合在论文和组会中解释为：一个围绕“预测-校核-调度-报告”闭环构造的工程评测集，而不是普通问答数据集。

数据集指纹

40

20 / 20

两类任务严格对半，避免 benchmark 只偏向其中一侧。
10 × 4

10 个类别，每类 4 个实例，既有广度也有可分析的重复结构。
40
唯一目标变量
每个场景绑定唯一 target boundary variable，保证评分和诊断可追踪。

任务结构

Prediction

给定扰动，预测目标边界变量

模型需要根据输入描述识别扰动对象、扰动方向、时间范围与预测目标，并输出结构化预测值或趋势解释。它主要考察物理合理性、证据支撑和约束一致性。

Dispatch

给定工况，提出可执行调度建议

模型不仅要识别当前风险或目标，还要比较候选动作、说明排序依据，并给出推荐操作与工程解释。它主要考察搜索能力、安全性、适应性与最终建议质量。

为什么这样设计

真实对象锚定

场景使用具体站点、压缩机、阀门、支路等对象名与边界变量名，而不是抽象占位符。这让错误分析可以直接回到工程对象层面。

单轮压缩

把原本可能是多轮的人机交互压缩为单轮任务，便于控制输入长度、统一评测口径，也更适合大规模自动跑分。

预测 / 调度分离

预测侧更关注数值趋势和物理一致性，调度侧更关注候选比较、约束规避与操作建议。分开设计后，论文展示会更清晰。

评测器友好

输入模板和输出字段都围绕 evaluator 能读取的结构来组织，例如目标变量、扰动设定、偏好约束和报告工件，因此结果可自动审计。

类别布局

P1

富余抬升与高压能耗

关注富余侧高压、局部过压和能耗抬升，适合检验模型对高压与冗余传输的敏感性。

示例变量：
T_006:SNQ / E_109:SNQ / C_019:SP_out / T_005:SP
P2

受限供给与需求缺口

关注源头受限、下游缺供和不同站点需求不均衡，适合看预测是否捕捉短缺传播。

示例变量：
T_003:SNQ / E_119:SNQ / E_082:SNQ / T_007:SNQ
P3

压缩机与工况切换

关注压缩机出口压力、启停状态和工况切换，适合检验设备级响应推断。

示例变量：
C_014:SP_out / C_021:SP_out / C_008:ST / C_022:SP_out
P4

调节阀与支路流量再分配

关注支路流量和阀门速度变化引发的再分配，强调局部操作对全网边界的连锁影响。

示例变量：
B_233:FR / B_317:FR / R_004:SPD / R_006:ST
P5

多元扰动叠加

把支路、阀门与边界需求的变化叠加在一起，用于观察模型在复杂场景下是否还能维持稳定预测。

示例变量：
B_286:FR / R_001:SPD / B_341:FR / R_007:SPD

调度侧 D1-D5 与预测侧共享同一工程底座，但更强调“风险识别 - 候选比较 - 推荐动作 - 报告交付”。在汇报中可以把 D1-D5 概括为：供需平衡调度、压缩机方案切换、支路重分配、安全约束规避与组合干预五类问题。
