PIPEFORMER EVALUATION

PipeFormer 评测方法：从运行轨迹到论文指标

评测器的目标不是只看最终一句答案，而是把 Agent 在管网场景中的完整工作拆成可核验的五组分数。它既读取结构化结果，也读取 trace、候选仿真、报告工件和 LLM judge 反馈，因此更接近工程评审而不是单点问答打分。

评测闭环：读取场景真值与运行产物，执行 G1-G5 评分，再输出总分、分组分和可回溯 artifact。

在论文里可以把它解释为：一个把工程正确性、约束一致性、证据支撑、调度建议和报告可用性统一起来的 evaluator。

对外展示时不必执着于 G1-G5 名字本身，更建议映射成预测准确性、工程可行性、证据质量、调度质量和报告可用性。

五组评分

G1

目标识别与任务完成

检查模型是否抓住正确任务、正确目标变量和场景要求，避免答非所问。

面向论文：任务完成度
G2

数值或候选结果正确性

预测侧看数值接近程度，调度侧看候选排序与推荐动作是否贴近 evaluator 参考。

面向论文：预测 / 调度正确性
G3

工程约束与证据支撑

检查边界约束、正值约束、设备包络以及解释中是否引用了足够的工程证据。

面向论文：可行性与证据链
G4

最终建议与诊断质量

检查最终回答是否把候选比较、排序理由、风险规避和推荐方案表达清楚。

面向论文：决策质量
G5

报告与交付物可用性

检查关键工件是否存在，并结合 rubric judge 评估报告的完整性、清晰度和可审计性。

面向论文：报告可用性

执行流程

STEP 1

读取数据集场景

从数据集里解析任务类型、目标变量、扰动对象、时间范围和工程偏好，形成 evaluator 输入骨架。

STEP 2

收集运行产物

读取 normalized answer、trace manifest、候选仿真目录、report 及运行期 token/cost 指标。

STEP 3

构造参考信息

预测任务读取目标边界真值；调度任务则基于候选仿真结果和工程偏好构造 evaluator 侧参考排序。

STEP 4

执行 G1-G5

规则检查与 LLM judge 混合打分，既保证结构化审计，也保留对解释质量与报告质量的弹性判断。

STEP 5

写出论文产物

最终生成每 case 明细、分组统计、总分汇总和可视化输入，便于论文表格与 badcase 分析。

真值来源与口径

Prediction：真值来自目标边界变量

预测类场景的主要真值来自数据集与仿真结果中对应的 target boundary variable。评测器围绕该变量比较数值误差、趋势方向和解释中的物理一致性。

Dispatch：真值来自候选仿真与工程偏好

调度类场景不依赖单个人工金标动作，而是根据候选方案仿真输出、约束满足情况和工程偏好，在 evaluator 侧形成参考排序，再检查模型建议是否匹配。
